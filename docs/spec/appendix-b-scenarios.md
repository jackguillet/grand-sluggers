# Appendix B — Scenario matrix (acceptance)

Each scenario is a headless sim test: set the state, script the inputs (human seat commands or "CPU"), assert the outcome **and** the reason (which out type, which bag, which runner). A scenario is green only when it passes for the human seat *and* the CPU seat where both exist. Unity's job is to show it; the gate is `dotnet test`, then a sitting.

**Coverage.** Every row carries its id in a test name in `src/GrandSluggers.Sim.Tests`: S-01 … S-93 (plus S-24b, S-55b and S-58b) across the scenario suites, S-94 … S-99 in `ControlScenarioTests`, S-101 … S-106 (plus S-106b) in `PitchSelectionScenarioTests`, S-107 … S-113 in `PitchFamilyTrialScenarioTests`, S-114 … S-120 in `CpuPitcherScenarioTests`, S-124 … S-127 in `SharedWindowScenarioTests`, S-134 … S-137 in `CursorOvalScenarioTests` and S-141 … S-143 in `CpuReadScenarioTests` (S-04 and S-28 have rows there too).
S-49 with the square (the crashing corners, the catcher's pop, the force back into 2B's glove) is `BuntScenarioTests`, and S-97's in-air twin (the liner SS reaches past the lip) is green on both seats. The pitch-family and window rows stand on the shipped root and assert relationships only, so a number may move without editing a test; a table that authors a removed key is refused by name (S-120, S-126). S-114 and S-124 are retired rows. Nothing in the matrix is open.
